## 실제 재료로 시험할 것
1. **1440p 렌더**: `npx remotion render src/index.ts Mongol01 /tmp/t.mp4 --frames=0-30 --scale=1.3333333333333333` → `npx remotion ffprobe -v error -show_entries stream=width,height -of csv /tmp/t.mp4`가 2560,1440이고 글자·캐릭터 배치가 1080p 때와 같은지
2. **캐릭터·효과음 큐가 렌더에 들어가는지** (짧게 렌더해 보기)
3. **목소리 끝 지지직 하네스**: `.venv/bin/python -I scripts/check-voice.py <장면표>` - 실제 목소리에서 정상 대사를 잘라내지 않는지(오탐), 지지직을 잡는지. `cast.py tail`·`clarity` 수정이 실제 소리를 바꾸지 않았는지 들어 보기
4. **입 모양**: `.venv/bin/python -I audio/characters.py mouth <장면표>` → 편집기 미리보기에서 입이 목소리에 맞는지
5. **문장 단위 자막**: 편집기 왼쪽 "자막 파일" → 시간이 맞는지
6. **편집기 길이 어림**(글자 수 기준)이 실제 목소리 길이와 얼마나 다른지 - 크면 `editor/app.tsx`·`scripts/check-length.py`·`scripts/check-pacing.py` estimate 계수 조정 (세 곳 같게)

## 개인 맥(집)·윈도우 PC에서 처음 작업할 때 (2026-10-21 사용자)
- `git clone` (또는 `git pull`) 후 **`./setup.sh`** 를 먼저 돌린다 - 노드·파이썬 환경, 오케스트라 음원(VSCO 2 CE, 약 5GB)과 sfizz 빌드, 입 모양(Rhubarb), 깊이 모델, Blender를 설치·받음
- 배경음악(`public/bgm/*.wav`, git에 없음)은 setup.sh가 없으면 자동으로 렌더한다 - 곡 이름으로 무작위 값을 고정해서 회사 맥과 같은 곡이 나옴 (처음엔 음원 5GB 받기·엔진 빌드로 몇 분)
- 직접 옮길 것은 키 `secrets/`(권한 600)뿐
- 1편 제작을 시작한 뒤에는 목소리를 만든 맥에서 `public/ep/`·`audio/.tts-cache/`(·`public/sfx/my/`)도 같이 옮긴다 - 안 옮기면 같은 목소리를 다시 만들어 무료·Gemini 한도를 또 씀. 되도록 한 편의 목소리는 한 맥에서
- 두 맥에서 같은 편을 동시에 고치지 않기 (푸시 → 풀 순서)
- **윈도우 PC**: `git clone` 후 **`setup.cmd`** (setup.ps1, 03 윈도우). 맥 없이 만든 윈도우 코드라 처음 한 번 아래를 차례로 확인하고, 막힌 곳은 고친 뒤 03 윈도우에 적기
  1. `setup.cmd`가 끝까지 가는지 (UAC 창 승인), 마지막 도구 표에 "없음"이 없는지 - 새 PowerShell 창에서 `node scripts/tools.mjs`·`.venv\Scripts\python -I scripts\tools.py` 다시
  2. 한글: `.venv\Scripts\python -c "import sys; print(sys.flags.utf8_mode)"`가 1, `.venv\Scripts\python -I scripts\check-text.py episodes\mongol-01\ep.json`이 한글을 깨지 않고 찍는지
  3. 검사기: `check-layout.py`·`check-pacing.py`·`check-length.py`·`check-screen.py`를 `episodes/mongol-01/ep.json`으로 - 맥과 같은 개수가 나오는지
  4. 렌더 설정: `node node_modules/@remotion/cli/remotion-cli.js still src/index.ts Thumb out/x.png` (크롬 경로·angle), `node scripts/thumbs.mjs episodes/<편>/thumbs.json` (--props 한글)
  5. `node scripts/make-episode.mjs episodes/<편>/ep.json <컴포지션> out/<편>.mp4 --dry-run` → 실제로 한 편 (목소리가 있는 편으로) - 실패한 단계에서 멈추는지, 깜빡임 검사·.checked가 맞는지
  6. 편집기 `npm run editor` → http://localhost:4600: 검사 칸, 소리 파일 끌어다 넣기(ffmpeg.exe), 자막 파일, 캐릭터 만들기, 대사 다시 만들기
  7. 브금: `.venv\Scripts\python -I audio\make_bgm.py <곡>` (sfizz_render.exe·fluidsynth.exe) - 맥 것과 들어 보고 차이가 크면 `setup.cmd -BuildSfizz`
  8. 입 모양 `audio\characters.py mouth`(rhubarb.exe), 효과음 `audio\make_sfx.py`(7z 풀기·ffmpeg.exe), 옛 그림 2.5D `scripts\parallax.py`(onnxruntime)
  9. 시네마틱: `scripts\scene-frames.py`가 Blender를 찾는지 - `blender/render_shot.py`가 아직 `.venv/bin/python`을 직접 써서 윈도우에선 막힘 (blender 담당이 `scripts/tools.py`의 `python()`으로 바꿔야 함)
  9-1. 기울인 지도 장면(WebGL판, 2026-10-22): chronomap 개발 서버를 켜고 `node scripts/map-scene.mjs --scene episodes/test/maps/kalka-swarm.json --only 0.6` 한 장 - d3d11에서 땅·부대가 맥 것과 같은지, Cliopatria 받기·풀기(Expand-Archive)가 되는지
  10. `node scripts/tools.mjs open https://example.com/?a=1&b=2` (& 든 주소가 그대로 열리는지), `node scripts/youtube.mjs` 로그인 창, `node scripts/tts.mjs savekey`(클립보드)
