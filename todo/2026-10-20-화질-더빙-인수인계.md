# 인수인계: 1440p 화질 개선 + 자동 더빙 정리 (2026-10-20)

작업을 이어받는 AI에게. 먼저 `docs/guide/`를 다 읽는다 (CLAUDE.md 규칙). 아래는 그 세션에서 바꾼 것과 남은 일이다.

## 배경
- 몽골 1편(qY1J4MPUUOw, 비공개)을 점검했더니 유튜브 **자동 더빙**이 켜져 있어 21개 언어 AI 더빙이 붙고, 우리 스페인어 더빙은 빠져 있었다. 한국어 트랙은 우리 더빙이 맞음(사용자가 들어서 확인 - 트랙 ID `ko.10`만 보고는 구분 안 됨)
- 자동 더빙은 사용자가 **설정 → 채널 → 고급 설정 → 자동 더빙 허용 해제**로 껐다(저장 완료). 업로드 기본 설정이 아니라 채널 쪽에 있다
- 사용자가 **1·2편을 유튜브에서 지우고 다시 만든다**. 그래서 기존 영상 정리는 할 필요 없음
- 화질 점검 결과 지도가 흐렸다: 캡처 2560×1440인데 장면표 확대가 최대 3.0배(1편 확대 지점 128개 중 72개가 원본 해상도 초과) + 렌더 JPEG 기본 화질 80

## 이미 바꾼 것 (커밋 안 됨 - 커밋은 사용자가 요청할 때만, Co-Authored-By 넣지 않음)
- `remotion.config.ts`: `Config.setJpegQuality(95)`
- `scripts/make-episode.sh`: 긴 영상 렌더에 `--scale=1.3333333333333333` → 화면 배치는 1920×1080 그대로, 출력 2560×1440(1440p). 쇼츠·썸네일·배너는 영향 없음
- `docs/guide/02-제작-결정.md`: 지도 선명도 규칙(확대 z ≤ 캡처 폭 ÷ 2560), 1440p 렌더 결정, JPEG 95
- `docs/guide/03-만드는-법.md`: 지도 캡처 기본 크기 2560x1440, 업로드 0단계(자동 더빙 끄기)
- `docs/guide/04-사고-기록.md`: 자동 더빙 사고, 지도 흐림 사고
- `docs/guide/05-외부-서비스.md`: 자동 더빙 끔 기록

## 남은 일
1. **1440p 렌더 검증 (아직 안 됨)**: 작업한 맥에 렌더 재료(`public/ep/`, `public/demo/` 등)가 없어 시험 렌더를 못 했다. 재료가 있는 컴퓨터에서 짧게 렌더해 확인:
   `npx remotion render src/index.ts Mongol01 /tmp/t.mp4 --frames=0-30 --scale=1.3333333333333333`
   → `npx remotion ffprobe -v error -show_entries stream=width,height -of csv /tmp/t.mp4` 가 2560,1440 인지, 글자·캐릭터 배치가 1080p 때와 같은지 눈으로 확인
2. **1·2편 지도 다시 캡처**: `clean.mjs <세트> 2560x1440 ...`. 캡처 창이 넓어지면 보이는 범위가 달라지니 휠 확대 칸 수를 다시 맞춘다
3. **장면표 확대값 점검**: `episodes/mongol-01/ep.json`, `mongol-02/ep.json`의 `show.from/to` 세 번째 값(z)이 `캡처 폭 ÷ 2560`을 넘는 곳을 찾아 고친다. 더 당겨야 하는 장면은 사이트에서 확대한 세트를 따로 캡처해 그 세트에서 z를 낮게 쓴다 (`mg-zoom` 방식)
4. (권장) **확대 한도 자동 검사**: `scripts/check-layout.py`에 "z × 2560 > 그림 실제 폭이면 멈춤"을 추가해 `make-episode.sh`가 잡게 한다. 지금은 사람이 지켜야 하는 규칙뿐이다. 넣으면 04 사고 기록의 "막는 장치"에 적는다
5. **다시 업로드할 때** (`03-만드는-법.md` 업로드 순서): 한국어·스페인어 더빙 둘 다 올리고 언어 페이지에서 오디오가 "게시됨"인지 확인. 편집기가 만드는 언어별 `.srt` 자막도 같이 올린다 (지금은 자동 자막만 있었음)
6. (논의만 됨, 결정 안 됨) 썸네일 글자가 영어라 한국어·스페인어 시청자도 영어를 본다. 사용자에게 언어별 썸네일이 필요한지 물어볼 것
