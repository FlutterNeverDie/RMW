## 원칙
- **확인 1 뒤에 영어를 바꾸지 않게 (2026-10-22 사용자: "왜 방금 고친 거야?")** - 영어 원어민 검토는 2단계, 한국어 다듬기는 2c에서 끝낸다. 확인 1 뒤 영어가 바뀌면 확인 1이 풀려 사용자가 같은 대본을 두 번 보게 됨. 스페인어 검토(6단계)만 확인 1 뒤
- **토큰은 '보는 데' 쓰고 '다시 읽는 데' 아낀다 (2026-10-21 사용자)**
  - 아낌없이: 그림 후보를 여러 장 직접 보고 고르기(위키미디어), **4단계에서 장면마다 최소 한 번 정지 화면을 찍어(`npx remotion still … --props`) 직접 보고** 어색한 배치·잘림·빈 화면을 고친 뒤 다시 찍기, 기울인 지도 장면의 경로·카메라·화살표 시점을 대사에 맞춰 시험 촬영(`map-scene.mjs --only`)
  - 아끼기: 긴 장면표를 처음부터 다시 읽지 않기(필요한 장면만), 통과한 검사 다시 돌리지 않기, 긴 작업은 새 세션에서 시작(쌓인 대화 비용)
- **사용자 확인 3번은 편집기에서** - Claude가 편집기를 그 편으로 열어 주고(`http://localhost:4600/?e=<편>`) 멈춘다. 사용자가 편집기에서 고치고 저장하면 그 내용으로 이어감
- **도장은 본 내용의 지문**을 담는다 (`episodes/<편>/pipeline.json`, `review/<언어>.json`). 앞 단계가 바뀌면 뒤 도장이 저절로 풀린다 - 대본을 고치면 확인 1·언어 검토·길이·목소리를 다시
- **Claude는 게이트에 걸린 곳만 고친다** - 코드 검사를 Claude 단계 사이에 둬서 토큰을 아낀다. 전체를 다시 읽고 다시 쓰지 않는다
- 캐릭터 그림·입 모양·검사·렌더는 코드라 토큰이 들지 않는다
- 업로드는 API로 (`youtube.mjs`, `uploads/<편>.json` 그대로) - 영상·언어별 제목·설명·태그·썸네일 1번까지. 더빙 트랙·자막·재생목록·최종 화면은 스튜디오 (03 업로드). 감사 통과 전엔 비공개로 잠김

## 사실 검증 (2026-10-21, 최상위 원칙 "인류 최고의 영상")
- 재미 보강 다음, 확인 1 전. 재미 보강이 대본을 고치니 그 뒤에 한 번만 본다. 방법은 `.claude/commands/factcheck.md`
- `episodes/<편>/facts.json` - 주장마다 판정(ok·disputed·wrong·unverified)과 출처(제목·ref·원문 한 줄). 장면 대사 지문으로 "확인함"을 표시해서 **대사를 고치면 그 장면만 다시 열린다** (다시 돌릴 때 바뀐 장면만 읽음 - 토큰 아끼기)
- 논란(disputed) 주장이 있는 장면은 대사에 "chroniclers claimed"·"maybe"·"up to" 같은 말이 있어야 통과 (01 원칙)
- 설명란 출처: `factcheck.py sources --merge`가 확인에 쓴 출처를 meta.json `sources`에 더하고 `upload-info.py`가 언어별 설명에 넣는다

## 비교 검토 (2026-10-21, 확인 1·3 직전)
- 같은 주제 조회수 높은 영상 2~3개(별별역사·Epic History TV·Kings and Generals 등, 07)와 우리 편을 **7개 축 - 훅 · 알아듣기 쉬움 · 리듬 · 화면 · 소리 · 감정 · 정확성**으로 나란히 놓고, 모든 축에서 같거나 나아야 한다. 못한 축은 고치거나 고칠 일을 적는다
- 유튜브 영상은 받지 않는다. 참고 영상은 Claude가 보고·읽은 것(설명·자막·댓글·분석 글)을 적고, 프레임은 우리 렌더에서만 뽑는다
- `episodes/<편>/compare.json`:
  ```
  {"refs": [{"title", "channel", "url", "views", "length", "first30": "첫 30초에 하는 일", "structure": "구성",
             "pacing": "리듬 설명", "sec_per_change": 4.5 (잴 수 있으면), "take": "가져올 점", "moments": [{"t": 5, "what": "..."}]}],
   "script": {"axes": {"hook": {"best": "참고 영상 중 최고가 하는 것", "ours": "우리", "rate": "better|equal|worse", "fix": "worse면 필수"}, "clarity": ..., "pacing": ..., "visuals": ..., "sound": ..., "emotion": ..., "accuracy": ...}, "summary": "..."},
   "render": {"axes": {...같은 7개}}}
  ```
  `fp`·`date`는 `compare.py stamp`가 채운다 (대본·렌더가 바뀌면 지문이 달라져 다시 비교)
- 우리 쪽 수치: `compare.py ours` (길이, 화면 바뀜 평균 초 - 목소리 전엔 어림, 첫 30초 장면)
- `compare.py report` → `~/hwm/<meta.folder>/<이름>_비교 검토.html`: 참고 영상 카드 + 축별 표 + (렌더가 있으면) 우리 렌더의 같은 시각 프레임(0·2·5·10·15·20·30초, 그 뒤 1분마다, 참고 영상 moments 시각). 판단은 사용자가

## Gemini 목소리 (무료, 모델당 하루 10번)
- 인물 대사 연기와 AI 음성 검수에 쓴다 (사용자: 품질 괜찮음). 결과는 캐시돼서 같은 대사는 다시 부르지 않는다
- `scripts/gemini-tts.mjs`가 하루 사용량을 기록(`audio/.gemini-usage.json`)하고, 다 쓴 모델은 부르지 않는다. 남은 양: `node scripts/gemini-tts.mjs quota`
- 한도가 차면 Chirp가 대신하고 `voice_episode.py`가 그 줄을 알려 준다 → 다음 날 다시 돌리면 캐시 덕에 남은 줄만 Gemini로 채운다
- 아껴 쓰기: 연기가 필요한 배역(cast.json `direction`)만 Gemini. 내레이터는 Chirp
- **유료 전환 (결정 2026-10-20, 적용은 사용자가 원할 때)**: 연기 대사만 유료, 내레이션은 계속 Chirp 무료. gemini-3.8-flash-tts 기준 편당 약 60~100원(2027년부터 2배). 바꾸는 법: 사용자가 AI Studio에서 그 프로젝트에 결제 연결 + 월 예산 알림 → `touch secrets/gemini_paid` (하루 한도 기록을 끄고 하루에 끝냄). 되돌리려면 그 파일 삭제
